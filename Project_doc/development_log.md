# Development Log

## 2026-08-21

### 1. 리밸런싱 비교 기능 추가

기존에는 Buy & Hold 기준으로만 백테스트가 가능했으나, 리밸런싱 조건을 선택적으로 적용해 비교할 수 있도록 UI/실행 로직을 개편.

**모드 1 — 포트폴리오 1개**
- 목적: 동일 포트폴리오에 대해 Buy & Hold vs 리밸런싱 주기별 성과 비교
- BH는 항상 고정 포함 (해제 불가)
- 리밸런싱 주기(매월/매분기/매년)는 다중 선택 가능 → 선택한 만큼 라인 추가 (최대 4개 + BH)
- 종목이 1개뿐인 경우 리밸런싱이 의미가 없으므로 선택 UI 비활성화 + 안내 문구 표시

**모드 2 — 포트폴리오 2개 이상**
- 목적: 동일한 리밸런싱 기준 하에서 포트폴리오 간 성과 비교
- 리밸런싱 방식은 전역에서 1개만 선택 (없음(BH) 또는 매월/매분기/매년), 기본값은 "없음(BH)"
- 선택한 기준이 모든 포트폴리오에 동일하게 적용됨

**구현 메모**
- `backtest_engine.py`는 수정 없음 — 기존에 `rebalance_freq` 파라미터를 이미 지원하고 있었음
- `app.py`의 포트폴리오 설정 UI와 실행 루프만 수정
  - 각 포트폴리오 config에 `rebalance_list`(적용할 리밸런싱 주기 목록) 추가
  - 실행 시 `rebalance_list`를 순회하며 반복 실행, 라인이 2개 이상이면 `"포트폴리오명 - 주기"` 형태로 이름을 붙여 결과 딕셔너리에 저장 → 기존 그래프/표 렌더링 로직 그대로 재사용
- 벤치마크는 항상 `rebalance_freq='none'`(BH) 고정 — 단일 종목이라 리밸런싱 대상이 없어 모드와 무관하게 결과 동일

### 2. 시작일(연도) 제한 완화 및 입력 UX 개선

- 기존: `st.date_input` 캘린더 위젯 사용, `min_value=1970-01-01`
- 문제: 브라우저 캘린더 드롭다운이 가상 스크롤 방식이라 연도를 큰 폭으로 거슬러 올라가기 불편함(10년 단위 점프)
- 변경: 시작일을 연/월/일 3개의 `st.number_input`으로 분리
  - 연도: 1900 ~ 올해, 직접 타이핑 또는 스핀 화살표(▲▼)로 1년 단위 자유 이동
  - 존재하지 않는 날짜(예: 2월 30일) 입력 시 에러 메시지 표시 후 중단
  - 시작일이 오늘보다 늦으면 자동으로 오늘 날짜로 조정 + 경고 표시
- 기존 로직(종목 실제 데이터가 지정 시작일보다 늦을 경우 공통 시작일로 자동 조정 + 안내 문구)은 변경 없이 그대로 유지
- 부가 수정: `load_price_data` 호출 시 날짜 포맷을 `strftime('%Y-%m-%d')`로 명시하여 `pd.Timestamp`의 시간 정보(`00:00:00`)가 API 호출에 섞여 들어가는 것을 방지
